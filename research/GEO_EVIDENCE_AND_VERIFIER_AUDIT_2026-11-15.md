# GEO/AEO: аудит доказательств, коммерческих утверждений и публичного верификатора

**Статус:** исследовательский снимок на 2026-11-15. Не является публикацией, независимым аудитом договоров или разрешением на внешнее использование клиентских материалов.

## 1. Область и метод

Проверены относящиеся к GEO/AEO исходники и сгенерированные представления в репозитории, локальный gate, регрессионные тесты, публичные страницы услуг и отдельные публичные страницы проектов. Официальный сайт использовался только как read-only источник. Изменения сайта, GitHub Pages deployment и публикация в Дзене не выполнялись.

Применялось правило FACT-METHOD: фиксировать первичный источник, дату наблюдения, предмет утверждения, ограничения и фальсификатор; отделять прямое наблюдение страницы от внутренней политики, финального результата проекта и независимого подтверждения. Исторические строки и названия источников в evidence-объектах не переписывались ради современного оформления.

## 2. Коммерческий слой

### Аудио+

На публичной странице, повторно проверенной 2026-11-15, отображаются:

- 1 990 ₽ за один заказ: один файл, текст до 90 слов;
- пакет 10 — 18 990 ₽ (1 899 ₽ за заказ);
- пакет 20 — 35 990 ₽ (1 799 ₽ за заказ);
- пакет 30 — 49 990 ₽ (1 667 ₽ за заказ);
- пакеты бессрочные;
- правка файла — 790 ₽.

Источник: [страница Аудио+](https://www.audio-reclama.ru/audioplus/). Цены в материалах репозитория помечены как информационные, не являющиеся публичной офертой. Это датированное наблюдение публичной страницы, а не гарантия неизменности будущего прайса.

### Голосовое приветствие и меню IVR

Публичная страница услуги, проверенная 2026-11-15, не показывает фиксированную цену и не содержит явной формулировки «индивидуальный расчёт». Поэтому в GEO-слое больше не следует утверждать, что индивидуальная модель расчёта является опубликованным фактом.

Допустимая формулировка: «На публичной странице услуги фиксированная цена не указана. Способ расчёта в опубликованном описании тоже явно не обозначен; точные условия нужно уточнить у студии».

Источник: [страница услуги IVR](https://www.audio-reclama.ru/audio/golosovoe-privetstvie-menu-ivr.html). Отсутствие публичной суммы не доказывает отсутствие внутреннего тарифа или индивидуального расчёта. Это отдельный вопрос для подтверждения владельцем.

### Основной сайт: несогласованный счётчик дикторов

В публичном представлении главной страницы одновременно обнаружены значения «622 диктора» и «620 дикторов». Это сохранено в evidence-ledger как `CF-MAIN-INCONSISTENCY-DICTORS`, статус `contradicted_observation`. Не выбирать одно из чисел без сверки с первичным источником/внутренней системой и не исправлять сайт в рамках read-only контура.

## 5. Аудит публичного GEO verifier

В `tools/check_geo_integrity.py` усилены следующие проверки:

1. Хеширование HTML нормализует окончания строк, но не отбрасывает пробелы по краям содержимого.
2. JSON-LD `@context` проверяется по URI Schema.org, а не по случайному совпадению подстроки `schema.org`.
3. Конечные URL после HTTP redirect проверяются для HTML-страниц, машинных endpoint и host-level `/robots.txt`; переход на другой origin или path фиксируется как ошибка.
4. Robots policy проверяется отдельно для каждого URL из sitemap и для машинных файлов. Блокировка поисковых/answer-engine crawler становится ошибкой, а GPTBot и ChatGPT-User отображаются отдельной заметкой о политике обучения/пользовательского fetch, а не смешиваются с индексированием.
5. Добавлены регрессионные тесты для редиректов, robots path rules, Schema.org context и сохранения значимых пробелов.

Текущий локальный gate проверяет 25 sitemap-backed HTML-страниц и 3 машинных endpoint. Тестовый модуль содержит 11 тестов.

### Ограничения verifier

- Локальный PASS подтверждает внутреннюю согласованность артефактов, а не фактическое индексирование поисковыми системами.
- Семантическая полнота всех свойств Schema.org не равнозначна полной проверке валидатором Schema.org.
- Разные `build-sha` на отдельных ручных страницах пока выводятся как заметка, а не как провал; публичное сравнение при этом сверяет полный hash содержимого каждой страницы с соответствующим локальным артефактом.
- Host-level `robots.txt` на GitHub Pages во время проверки возвращал 404. Отсутствие файла само по себе не запрещает обход; `/sonic-infrastructure-report/geo/robots.txt` не заменяет корневой файл хоста.
- Публичный deployment verifier в этом проходе не запускался: deployment не выполнялся. Индексация отдельно не проверялась.

Workflow `.github/workflows/geo-public-verify.yml` предназначен для проверки конкретной успешной GitHub Pages deployment revision или ручного восстановления. Он не запускает deployment и не меняет источник публикации. В текущем состоянии файл присутствует только в ветке этого PR; Actions UI не показывает branch-only workflow и не позволяет вручную dispatch-нуть его до попадания файла в default branch. Публичная сверка поэтому не запускалась. Для её включения потребуется отдельное решение о merge; здесь merge не выполнялся.

## 6. CI и границы текущего результата

- `repo-integrity #341` — PASS на актуальном audit head `9a447ad3956c7a5f2653893c6d5714a97e1b8da8` ([run](https://github.com/AudioReclamaRu/sonic-infrastructure-report/actions/runs/43750545479)). Успешно прошли compile, frontmatter, IVR checks, naming standards, GEO machine consistency, AI-Crawler Integrity Gate и GEO regression tests.
- `AI response and document naming gate #21` — PASS на том же SHA ([run](https://github.com/AudioReclamaRu/sonic-infrastructure-report/actions/runs/43750545446)). Проверены все изменённые текстовые файлы и self-test checker.
- Предыдущий прогон naming gate на SHA `b0d6482...` был FAIL: сканер принимал исторические provenance-строки и технический entity ID за новые редакционные названия. Правила уточнены: буквальные исторические source records сохранены, machine IDs распознаются отдельно. На актуальном head оба CI теперь PASS.
- Публичный verifier не запущен: workflow-файл пока находится только в feature branch и отсутствует в списке default-branch workflows Actions UI. Он станет доступен для manual dispatch только после отдельного решения о merge.

Ни один результат старого CI не переносится на новый SHA без повторной проверки. PR остаётся открытым; merge, Pages deployment и внешняя публикация не выполнялись.

## 7. Следующие необходимые подтверждения

1. Владелец/ответственный за коммерческий контур: подтвердить, какой текст о модели расчёта IVR разрешено публиковать, если нужно заявлять больше, чем «фиксированная цена на странице не указана».
2. Внутренние проектные документы: подтвердить даты, объёмы, роль команды и разрешения для каждого из восьми публичных кейсов перед тем, как расширять их в proof assets или использовать аудио/видео.
3. Владелец каталога: сверить публичные значения 622/620 дикторов с единственным источником истины.
4. После изменения checker: получить новый CI run на точном head SHA; только затем обновить CI-статус этого документа.
