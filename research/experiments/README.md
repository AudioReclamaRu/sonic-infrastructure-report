# Реестр экспериментов

Здесь хранятся только структурированные записи реальных или планируемых экспериментов. План, синтетический fixture и завершённый запуск — разные статусы; не выдавать один за другой.

## Создание записи

1. Скопировать \`experiment-record.template.json\` в \`EXP-YYYY-NNN-short-name.json\`.
2. Назначить уникальный \`experiment_id\` вида \`EXP-...\`.
3. Заполнить вопрос, гипотезу, нулевую гипотезу, фальсификатор, переменные, контроль, происхождение данных и analysis plan.
4. Заполнить все шесть линз \`six_lenses\`: \`semiotics\`, \`ethology_behavior\`, \`chronobiology\`, \`ergonomics_human_factors\`, \`complex_systems\`, \`cryptology\`.
5. Установить честный статус. Не использовать \`COMPLETED\` или \`REPRODUCED\`, пока нет \`run_id\`, дат запуска, исходов, измерений, ограничений и evidence для каждой применимой линзы.

## Семантика статусов

- \`PROPOSED\` — идея и вопрос сформулированы, дизайн ещё не утверждён.
- \`PLANNED\` — протокол и переменные определены, запуск не начат.
- \`RUNNING\` — фактический запуск идёт.
- \`HOLD\` — существенный нерешённый риск/пробел блокирует дальнейший ход.
- \`COMPLETED\` — запуск завершён, записаны результаты и ограничения.
- \`REPRODUCED\` — запуск независимо повторён по версии протокола.
- \`FAILED\` — запуск выполнен, но процедура/система не прошла заранее заданные условия; результат и причина сохранены.

\`NOT_APPLICABLE\` требует предметного обоснования. \`NOT_ASSESSED\` допустим в PROPOSED/PLANNED/RUNNING, но не позволяет закрыть запуск как COMPLETED/REPRODUCED/FAILED. Любая линза \`HOLD\` требует общего статуса \`HOLD\`.

## Автоматическая проверка

\`\`\`bash
python tools/check_experiment_records.py
python -m unittest discover -s tools/experiment_integrity/tests -v
\`\`\`

CI выполняет обе проверки при каждом push/pull request. Проверяются структура записи, шесть линз, основания N/A/NOT_ASSESSED, evidence для применимых линз, статусы запуска, происхождение данных, формат хешей и release approval.

Валидатор намеренно использует только стандартную библиотеку Python. Он проверяет критические условия проекта, но не реализует полную JSON Schema Draft 2020-12, не проверяет научную истинность, право, этическое разрешение или безопасность хранилища.

## Данные и приватность

В публичном Git хранить только разрешённые метаданные, агрегаты и ссылки на контролируемые хранилища. Не добавлять сырые записи, персональные/чувствительные данные, закрытые договоры, секреты, приватные ключи или неразрешённые материалы. \`SHA-256\` подтверждает совпадение с известным дайджестом, но не источник, авторство, истину или разрешение на использование.
