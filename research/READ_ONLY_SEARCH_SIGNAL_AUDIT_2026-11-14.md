# Поисковый сигнал Audio-Reclama.ru: read-only технический срез

**Дата проверки:** 2026-11-14  
**Статус:** зафиксированные наблюдения и приоритизированный план исправлений; не полный SEO-аудит и не измерение поисковой эффективности.  
**Граница:** сайт Audio-Reclama.ru проверялся только на чтение. Никакие страницы, метаданные, настройки, sitemap или публикационные механизмы не менялись.

## 1. Что именно проверено

Проверены в реальном времени:
- главная страница;
- robots.txt и sitemap.xml;
- коммерческие страницы аудиороликов, IVR, дикторов, переводов, видеопроизводства и сценариев;
- страница отзывов;
- отдельные страницы дикторов и страницы фильтров;
- перенаправление старого адреса /clients.html;
- отдельные URL из XML-карты сайта.

Инструментальный снимок не равен данным Google Search Console или Яндекс Вебмастера. Нельзя по нему определить позиции, показы, клики, органические сессии, выбранный поисковиком canonical, частоту запросов или конверсию.

## 2. Снимок структуры обхода

|---|---:|

| Уникальных URL | 1 186 |

| Страницы фильтров каталога | 308 |

Числа групп — счётчики по структуре URL, а не оценка ценности страниц. По выборке проверенных страниц каталог действительно содержит самостоятельные профили с именем, демо, языком/тембром и биографическим описанием. Поэтому автоматически закрывать весь каталог от индексации нельзя.

### Что доказано на конкретных URL

1. Два адреса профилей возвращают 404, но остаются в live sitemap:
   - [Наталья Беленькая](https://www.audio-reclama.ru/diktoryi/zhenskie-diktor-golosa/russian-diktor-natalia-belenkaia.html)
   - [Yavor — болгарский диктор](https://www.audio-reclama.ru/diktoryi/inostrannye-diktor-golosa/bulgarian-diktor-yavor.html)

   Это подтверждённые примеры, а не статистика всего каталога. В ограниченной проверочной выборке ещё одиннадцати адресов десять открылись с HTTP 200, один вернул 404; профиль Натальи Беленькой проверен отдельно. Все 703 профиля ещё не обходились.

2. /clients.html присутствует в sitemap, но при открытии завершается на /feedbacks.html с HTTP 200. Для карты сайта нужно использовать конечный предпочтительный URL, а не адрес, требующий перенаправления. Точный код промежуточного редиректа в этом срезе не фиксировался.

3. robots.txt доступен и явно указывает на https://www.audio-reclama.ru/sitemap.xml. Входной домен и HTTP-вариант нормализуются к HTTPS-хосту www. Проверенные коммерческие страницы открывались с HTTP 200. В выборке не обнаружен директивный noindex.

4. Все 1 186 адресов в sitemap уникальны. При этом XML не содержит lastmod, а для адресов выставлен changefreq=daily. Google не использует priority и changefreq как сигналы; lastmod следует добавлять только при наличии достоверной даты фактического изменения.

5. Число профилей и публичные счётчики требуют сверки: sitemap содержит 703 URL страниц профилей; главная показывает 622 диктора, страница переводов — 620. Это может быть разницей между активными записями, архивными профилями и разными способами подсчёта. Причина неизвестна; утверждать, что одна из цифр ошибочна, нельзя.

Официальные технические источники: [robots.txt](https://www.audio-reclama.ru/robots.txt), [sitemap.xml](https://www.audio-reclama.ru/sitemap.xml).

## 3. Приоритеты: что даст самый сильный прирост качества поискового сигнала

Приоритет здесь означает срочность и доказанность проблемы, а не измеренный поисковый спрос или прогноз роста трафика.

### P0 — очистить sitemap и каталог от несуществующих адресов

**Подтверждённая проблема:** два 404-профиля перечислены в sitemap; один старый URL раздела отзывов ведёт на конечный URL.

**Требуемое действие для администратора сайта:**
- проверить все URL в sitemap на конечный HTTP-код, число переходов и целевой URL;
- удалить из sitemap подтверждённые 404 и любые неактуальные адреса;
- адреса, у которых есть полноценная замена, перенаправить на наиболее близкую релевантную страницу; если замены нет — не перенаправлять на главную ради маскировки 404;
- проверить внутренние ссылки на удалённые профили;
- формировать sitemap только из предпочтительных URL, которые реально должны индексироваться и отвечают HTTP 200;
- публиковать lastmod только при точном времени содержательного изменения страницы.

**Проверка результата:** повторный обход всех 1 186 URL; ноль 404 и цепочек перенаправлений в sitemap; каждый URL ведёт на соответствующую индексируемую страницу. Сохранить список исключений с обоснованием.

Это первая задача: нет смысла усиливать внешние ссылки и публиковать новые материалы, пока карта обхода содержит несуществующие профили.

### P1 — сделать каталог дикторов понятной поисковику структурой людей

703 URL профилей — крупный самостоятельный пласт индексируемых сущностей. Проверенные профили содержат индивидуальные элементы: имя, демо, тембр, описание опыта, иногда образование, города работы и доступность.

**Предложение:**
- на каждой действующей и подтверждённой странице профиля использовать Person с данными, которые уже видны пользователю и разрешены к публичному отображению;
- связать человека с общей сущностью студии через единый стабильный @id, не создавать на каждой странице новую несвязанную организацию;
- указывать только проверяемые сведения: имя, URL профиля, изображение, публичное описание и профессиональную роль; не добавлять непроверенные награды, работодателей, цены, города и права на голос;
- построить явную и согласованную навигацию «каталог → язык/тип голоса → профиль»; BreadcrumbList добавлять только там, где соответствующие хлебные крошки действительно видны пользователю;
- проверить, что карточки каталога ссылаются на актуальные профили, а каждый профиль возвращает ссылку к правильной категории;
- отдельно сверить активный каталог с двумя публичными счётчиками 620/622 и списком 703 URL.

**Фильтры (308 URL):** не закрывать их массово. Для каждого типа фильтра проверить, что страница ведёт к реальным доступным голосам, имеет отличимое назначение и помогает выбрать. Пустые, почти одинаковые или бессмысленные комбинации требуют решения поштучно: оставить полезную страницу, объединить с основной категорией, задать корректный canonical или исключить из sitemap. Решение noindex не должно приниматься только по факту наличия фильтра.

### P1 — структурировать конкретные услуги, а не размножать общую Organization

На выборке страниц аудиороликов, IVR, дикторов, переводов и видео в JSON-LD обнаружена только общая сущность Organization; отдельные сущности Person, Service и BreadcrumbList в проверенных шаблонах не обнаружены.

**Предложение:**
- определить одну согласованную сущность организации с точным отображаемым брендом **Аудио-Реклама•ru**, устойчивым @id и предпочтительным URL сайта;
- проверить все ссылки sameAs: оставить только официальные профили, принадлежность которых подтверждена;
- на страницах фактически оказываемых услуг разметить видимую услугу через Service, связав её с организацией и самой страницей;
- не создавать фальшивые отзывы, цены, рейтинги, адреса, юридические идентификаторы, исполнителей или гарантии;
- не размечать собственные отзывы/виджеты Яндекса и Google как саморейтинг организации. Страница отзывов может ссылаться на независимые площадки, но не должна выдавать сторонние рейтинги за собственную оценку, пригодную для Google review snippets.

Структурированные данные должны точно описывать видимый контент и не гарантируют расширенный результат или более высокую позицию. Это слой семантической согласованности, а не трюк ранжирования.

### P1 — исправить противоречивые коммерческие обещания в сниппетных метаданных

На странице IVR метаописание обещает цену от 1 000 рублей и срок один день, но этих значений не удалось найти в видимом тексте страницы. При этом внутренний коммерческий GEO-слой в репозитории описывает расчёт IVR как индивидуальный. Это конкретное несоответствие между публичным метаописанием и текущей внутренней записью условий; актуальную цену и срок должен подтвердить владелец услуги.

**До подтверждения не переносить 1 000 рублей и один день в новые тексты, JSON-LD или рекламные материалы.** Администратору сайта — проверить, действуют ли обещания; затем синхронизировать description с фактическим предложением и видимым содержимым. Я не менял метаданные сайта.

### P2 — сделать заголовки и описания прямым ответом на запрос

Главная сейчас описывается метафорической фразой об «искусстве звука», которая не сообщает основные задачи студии. Коммерческие страницы в целом имеют тематические H1 и title, но некоторые title избыточны, а описание услуги не всегда раскрывает конкретный процесс.

Ниже — **редакционные предложения**, а не внесённые изменения. Их задача — ясно назвать услугу, дать поисковику и человеку точное резюме, побудить к релевантному действию без недоказанных гарантий.

| Страница | Предлагаемое meta description |
|---|---|
| Главная | «Аудио-Реклама•ru» — студия аудиопродакшна и озвучивания: рекламные аудиоролики, подбор и запись дикторов, голосовые меню IVR, перевод и локализация, производство видеороликов. |
| Радиоролики | Рекламные аудиоролики для радио: сценарий, кастинг диктора, запись, саунд-дизайн и лицензионная музыка. Послушайте примеры и отправьте бриф. |
| IVR | Голосовые приветствия, меню IVR и автоинформаторы для АТС, VoIP и мобильной телефонии. Подбор диктора, запись и подготовка файлов под требования вашей системы. |
| Каталог дикторов | Подбор и запись дикторов для рекламы, видео и корпоративных объявлений. Демозаписи, язык и тембр, студийная запись и онлайн-сессии; выберите голос или закажите кастинг. |
| Перевод и локализация | Перевод, локализация и озвучивание материалов на иностранных языках. Переводчики и дикторы — носители языка; работа с текстами, видео, программными интерфейсами и мультимедиа. |
| Видеопроизводство | Создание рекламных и корпоративных видеороликов: сценарий, съёмка, графика, анимация, монтаж и субтитры. Посмотрите примеры проектов и отправьте задачу. |

Дополнительная редактура: в title страницы видеопроизводства обнаружена опечатка «эксплнейнер»; корректная форма — «эксплейнер». Перед исправлением следует сверить окончательный заголовок с реальным набором услуг и редакционным решением владельца.

Не нужно повторять ключевые слова десятки раз, делать одинаковые descriptions для 1 186 URL или механически подгонять каждый заголовок под фиксированную длину. Заголовок должен точно описывать конкретную страницу; сниппет поисковик может составлять из текста страницы, а не брать description дословно.

## 4. Что не признано дефектом

- На проверенных страницах не обнаружен rel=canonical. Это повод расширить проверку, но не доказанный блокирующий дефект: основной хост и HTTPS уже нормализуются перенаправлениями, а sitemap использует www-HTTPS адреса. Сначала нужно проверить конечные ответы всех вариантов URL и выбранные поисковиком канонические адреса в панелях вебмастеров. Не добавлять canonical вслепую.
- Наличие 308 фильтров само по себе не означает SEO-мусор. Уникальный и полезный фильтр может соответствовать самостоятельному запросу.
- Нельзя добавлять AggregateRating для самих себя только потому, что на странице показаны рейтинги внешних платформ.
- priority и changefreq не являются рычагами ранжирования Google; менять их ради «SEO-оптимизации» не нужно.
- В этом срезе нет оснований говорить о санкциях, падении трафика, низких позициях или плохих Core Web Vitals.

## 5. Что измерить после технической очистки

Без этого невозможно выбрать страницы на основании реальных потребностей поисковиков. Нужен экспорт данных, а не догадки:

| Источник | Какие данные получить | Для чего |
|---|---|---|
| Google Search Console | Pages/Indexing, выбранные canonical, запросы, показы, клики, CTR, средняя позиция за 3–6 месяцев | Увидеть, какие URL и формулировки действительно получают поисковые показы; найти 404/исключённые и каннибализацию |
| Яндекс Вебмастер | Индексирование, диагностика, Sitemap, поисковые запросы/показы, ссылки | Сопоставить российский поисковый спрос и техническое состояние Яндекса |
| Wordstat | Точный регион, период, формулировки и частотность с зафиксированными параметрами | Разделить коммерческий спрос, проблемные вопросы и информационный интерес |
| CRM / обращения | Повторяющиеся вопросы и квалифицированные обращения, обезличенно | Проверить, какие поисковые задачи имеют реальную коммерческую связь |
| Серверные логи (если доступны) | Googlebot/YandexBot, URL, код ответа, частота и глубина обхода | Понять, как роботы расходуют обход на каталог и фильтры |

Для каждого кластера применять уже существующий problem-solutions/MEASUREMENT_PROTOCOL.md: запрос, язык/регион, источник, дата и период, текущая страница, показы/клики/CTR, ограничения. Сравнивать изменения по интервалам 2/4/8/12 недель, не приписывая причинность одной правке.

## 6. Последовательность исполнения

1. **Сначала** полный машинный проход по 1 186 URL: конечный HTTP-код, redirects, canonical/hreflang, robots, sitemap membership, внутренние входящие ссылки. Исправить 404 и redirecting URLs в карте сайта.
2. **Затем** полный аудит 703 профилей и 308 фильтров: актуальность, дубли, пустые категории, публичные разрешения, внутренние связи, одна система подсчёта активных дикторов.
3. **Далее** согласовать коммерческие факты IVR и унифицировать метаданные главной и услуг.
4. **После** — внедрить корректный entity graph в код сайта уполномоченным администратором: Organization → Service / Person / BreadcrumbList, только там, где это соответствует видимой структуре.
5. **Затем измерить**, какие категории запросов действительно приводят людей на подходящие страницы, и оптимизировать следующую очередь по данным, а не по вкусу редактора.

### Критерии приёмки технического этапа

- В sitemap нет адресов, которые заканчиваются на 404, нецелевой редирект или неканонический дубль.
- Каждый профиль, оставленный для индексации, имеет конечный HTTP 200 и содержимое о конкретном человеке; удалённый профиль не остаётся в sitemap и внутренних карточках.
- Фильтр включён в sitemap только при наличии самостоятельной пользовательской ценности.
- Одинаковые публичные цифры каталога получены из одного актуального источника подсчёта или снабжены ясным определением.
- Метаданные не обещают неподтверждённые цены и сроки.
- JSON-LD совпадает с видимым содержимым; сущности связаны устойчивыми идентификаторами.
- Реальное состояние индексации проверено в Search Console и Яндекс Вебмастере.
