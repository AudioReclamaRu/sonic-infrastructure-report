# Первый first-party срез: источники трафика, AI-tagged входы и целостность аналитики

**Дата извлечения:** 21 ноября 2026 года.  
**Периоды:** Яндекс Метрика — 1–20 ноября 2026 года; Google Search Console — 18 августа–18 ноября 2026 года; GA4 — проверка доступных данных за 17–20 ноября 2026 года.  
**Режим:** только чтение существующих подключений; без изменения сайта, счётчиков, тегов, профилей или публикаций.

## 1. Главное решение

У «Аудио-Реклама•ru» уже есть полезный first-party сигнал, но сейчас измерительная система не позволяет честно связать его в одну воронку:

1. Google Search Console показывает поисковый спрос и клики по коммерческим страницам.
2. Подключённая Яндекс Метрика возвращает реальные записи сессий, источники и входные URL.
3. В части записей встречается UTM-метка `chatgpt.com`, то есть существуют визиты с таким помеченным источником.
4. GA4-коннектор за 17–20 ноября не вернул строк ни по сессиям, ни по событиям.
5. Количество возвращаемых строк Яндекс Метрики зависит от набора запрошенных полей. Поэтому полученные выборки пока нельзя считать полностью reconciled totals.
6. Сессии Метрики приходят с вариантом host без `www`, тогда как канонический URL по стандарту компании и выбранное GSC-свойство используют `www`. Причину и фактическую HTTP-нормализацию ещё нужно проверить.

**Решение:** ближайшая аналитическая работа — не новый SEO-отчёт и не новый контент. Сначала нужно нормализовать измерительную цепочку: один host policy, согласованные счётчики и подтверждённая карта целей. До этого не публиковать проценты AI-referral и не считать ID цели квалифицированной заявкой.

## 3. AI-tagged входы: что можно утверждать

Фильтр по `utm_source=chatgpt.com` возвращал **12–18 записей в зависимости от набора полей запроса**. В трёх более широких запросах появлялось 18 записей; запрос с дополнительным полем счётчика вернул 12. Поэтому корректный статус сейчас — **наблюдаемый AI-tagged сигнал с нестабильным количеством строк**, а не точное число переходов за период.

В варианте, вернувшем 18 записей:

- было 25 просмотров страниц;
- суммарная длительность по полю коннектора — 4 412 секунд;
- посадочные страницы преимущественно относились к публичному каталогу голосов и отдельным профилям дикторов;
- среди конечных путей встречались каталог/профили, одна статья о голосе, маршрут добавления озвучки и страница озвучки видео;
- поле `lastTrafficSource` для этих строк возвращало `direct`;
- referrer/источник перехода, UTM medium и UTM content не были заполнены.

### Что это означает

1. UTM-значение `chatgpt.com` присутствует в данных Метрики и не должно игнорироваться.
2. Оно **не доказывает**, что пользователь перешёл непосредственно из ответа ChatGPT: UTM-ссылка могла быть открыта, скопирована или передана дальше.
3. Оно не доказывает цитату или упоминание в ответе ИИ.
4. Это не квалифицированные лиды и не заказы.
5. Средняя длительность визита не является показателем качества: на неё влияют длинные открытые вкладки и отдельные выбросы.
6. Каталог голосов — логичный вход для части пользователей, но следующим действием должен быть понятный маршрут к соответствующей задаче, брифу и условиям заказа. Не нужно создавать ещё одну общую статью о выборе голоса: в репозитории уже существует `guides/choosing-a-voice.md`, а в problem-solutions/README.md указана существующая GEO-страница `geo/guides/kak-vybrat-golos/`.

### Целевые действия пока не расшифрованы

Поле `sessions.goalsID` содержит массивы идентификаторов целей. Но сами идентификаторы не объясняют, что именно произошло: просмотр страницы, глубина, JS-событие, отправка формы, клик по телефону или другое действие.

В выбранных чтениях у AI-tagged сессий присутствовали непустые массивы goal IDs, но это **не даёт права называть их заявками или конверсиями**. Для интерпретации требуется получить карту целей: ID → имя → тип → статус → условие срабатывания. Официальный интерфейс/API Яндекс Метрики предоставляет отдельный список целей, но используемый коннектор такую карту в текущей выгрузке не вернул.

## 5. Host и аналитическая целостность

Наблюдение из выбранной выгрузки Метрики: все стартовые URL использовали host-вариант без `www`. Между тем:

- обязательный канонический URL проекта — `https://www.audio-reclama.ru`;
- выбранное свойство Google Search Console — `https://www.audio-reclama.ru/`;
- отображаемое имя подключённого GA4 account/stream — `audio-reclama.ru`;
- проект OpenSEO использует доменную метку `audio-reclama.ru`.

Само различие написаний не доказывает ошибку. Возможны несколько объяснений: штатный редирект на canonical host, фактическая работа сайта на обоих host-вариантах, отличающиеся host-параметры счётчика или смешение потоков/свойств. Но до проверки нельзя считать, что данные GSC, GA4 и Метрики точно складываются в одну host-нормализованную систему.

### Обязательная read-only проверка

Для главной страницы и пяти коммерческих URL выполнить одинаковую проверку обоих host-вариантов:

1. HTTP status, конечный URL и полная цепочка редиректов;
2. `rel=canonical`, meta robots и X-Robots-Tag;
3. наличие и идентификатор счётчика Метрики;
4. наличие и идентификатор GA4 measurement stream;
5. host, сохраняемый в page/session payload;
6. отсутствие двойной отправки pageview при редиректе или переходе между host-вариантами.

Нельзя по одной Метрике объявлять, что канонический редирект сломан. Если подтвердится, что один host не нормализуется либо один и тот же визит попадает в два счётчика, подготовить минимальный diff и вынести его владельцу на отдельное разрешение.

| Приоритет | Работа | Критерий завершения |

| P1 | Проверить AI-tagged маршрут выбора голоса | Существующие страницы и ссылки сопоставлены с путём к релевантной услуге; нет нового дубля контента |
| P1 | Проверить GA4 collection | В Realtime/DebugView подтверждены page_view, source/medium, hostname и реальные форм-события; пустой API-экспорт не считается нулём |
| P2 | Зафиксировать native AI-citation baseline | Bing AI Performance и eligible consumer UI отдельно подключены/аттестованы; citation, mention, tagged visit и lead не смешиваются |

### Строгая семантика статусов

- `OBSERVED` — значение реально пришло из источника и записано с методом.
- `UNRECONCILED` — источник вернул противоречивые/разные количества строк при одинаковом периоде; нельзя публиковать доли от общего трафика.
- `UNMAPPED_GOAL` — ID цели найден, но не установлено её назначение и условие.
- `AI_TAGGED` — URL содержит `utm_source=chatgpt.com`; это не подтверждённый AI referral, citation или lead.
- `NOT_TESTED` — нет измерения.
- `BLOCKED_AUTH` — нужна авторизованная карта целей или Realtime/DebugView, недоступная через текущий read-only коннектор.

## 7. Источники и пределы

### Подключённые данные

- Яндекс Метрика, счётчик ID 1413317: выборки сессий за 1–20.11.2026; четыре пятидневных запроса с одинаковым набором полей для базовой таблицы.
- OpenSEO / Google Search Console, свойство `https://www.audio-reclama.ru/`: web-search performance за 18.08–18.11.2026; dimensions page/query.
- Windsor.ai / Google Analytics 4: запросы по сессиям и событиям за 17–20.11.2026 вернули пустые наборы строк. Это ограничение доступной выборки, не доказательство нулевых посещений/заявок.

### Официальная документация Яндекс

- [Поля сессий Яндекс Метрики](https://yandex.com/dev/metrika/en/logs/fields/visits): `startURL` описан как посадочная страница; `endURL` — конечная страница; `pageViews`, `visitDuration` и `goalsID` имеют отдельные значения.
- [Экспорт данных Метрики](https://yandex.com/support/metrica/en/pro/visits): сессии могут получать обновления по мере поступления новых данных; это важно при воспроизводимости выгрузок.
- [Методы API для списка целей](https://yandex.ru/dev/metrika/ru/management/openapi/goal/goals): список целей включает ID, имя, тип, статус и условия; без этой карты нельзя интерпретировать числовой Goal ID как лид.

### Ограничения

- Выгрузка не содержит доказательств AI-ответов, цитирования, сделок или выручки.
- UTM-параметр может жить дольше исходного перехода; он не заменяет referrer или запись исходного ответа.
- Goal ID не равен лиду, пока не проверены тип и условие.
- Средняя длительность сессии не является KPI качества.
- Различные количества строк для разных полевых схем не дают надёжного знаменателя для market share, channel share всего сайта или конверсии.
- Проверки live HTTP headers, robots, sitemap и тегов на обоих host-вариантах не были выполнены в этом цикле.
- Официальный сайт, настройки Метрики/GA4, внешние профили и публикации не менялись.
- Платные сервисы, кредиты и реклама не использовались.

## 8. Решение следующего цикла

Первый приоритет — закрыть измерительную целостность: canonical host, IDs тегов и карта целей. Второй — проверить уже существующий маршрут выбора голоса и не создавать новый материал поверх `guides/choosing-a-voice.md` и GEO-страницы выбора голоса. `search impression → search click / AI-tagged visit → service route → verified contact action → qualified enquiry`
