**Дата извлечения:** 21 ноября 2026 года.  
**Период:** 22 октября — 17 ноября 2026 года включительно (27 дней).  
**Источник:** существующее read-only подключение Яндекс Метрики; counter ID **1413317**.  
**Режим:** только чтение; настройки счётчика, сайта и событий не менялись.

## 2. Goal ID не равен заявке

В 88 из 118 записей присутствовал хотя бы один элемент в поле sessions__goalsid. Документация Яндекс Метрики определяет этот массив как ID целей, достигнутых в рамках визита. Но коннектор вернул числовые ID без имени, типа и условия срабатывания.

Дополнительные поля были запрошены в том же запросе, с теми же датами, путями и идентификаторами визитов:

- sessions__goalsorder: непустых идентификаторов заказа не найдено;
- sessions__goalsprice: положительных значений цены цели не найдено;
- sessions__offlinecalltag и sessions__offlinecallurl: непустых значений не найдено;
- sessions__offlinecalltalkduration: положительной длительности звонка не найдено;
- sessions__offlinecallmissed: признаков пропущенного звонка не найдено.

Это означает только то, что перечисленные поля не были заполнены в возвращённых записях данного среза. Это **не доказывает отсутствие реальных заказов, звонков или обращений вне этих полей**.

В API Яндекс Метрики существует отдельный метод списка целей счётчика. Он возвращает, в том числе, ID, имя, тип, статус и условия. Пока такая карта не получена, ни один Goal ID из этой выгрузки нельзя уверенно назвать отправкой формы, кликом телефона, заявкой или продажей.

## 2.2. Словарь целей получен: структура и происхождение

21 ноября 2026 года владелец выполнил read-only запрос официального Management API с OAuth-правом `metrika:read` и передал JSON-ответ. Токен вводился локально в PowerShell, не передавался в чат и не включён в этот отчёт или CSV-артефакты. Настройки счётчика и определения целей не менялись.

В ответе API содержатся **88 верхнеуровневых целей**. Семь из них имеют тип `step` и содержат ещё **16 вложенных шагов**. Итого в словаре **104 именованные записи** с уникальными ID, если считать шаги составных целей отдельно. Все 104 записи имеют статус `Active`. Среди 88 верхнеуровневых записей 76 имеют источник `user`, 12 — `auto`. У каждой цели `default_price = 0`; это настройка оценочной цены цели, а не доказательство нулевой выручки.

Распределение типов верхнеуровневых целей: `action` — 62; `step` — 7; `number` — 6; `url` — 3; по одной цели типа `messenger`, `file`, `email`, `form`, `phone`, `social`, `payment_system`, `search`, `contact_data` и `contact_data_sent`.

Официальный метод, которым получен словарь:

`GET https://api-metrika.yandex.net/management/v1/counter/1413317/goals`

Он возвращает ID, имя, тип, статус и условия/параметры цели. В отличие от прежней статистической выгрузки, владелецкий JSON содержит само соответствие ID → определение цели.

## 2.5. Практический вывод для аналитики

Предыдущий показатель «88 визитов с Goal ID» теперь расшифрован: это визиты с набором в основном поведенческих микросигналов, а не 88 обращений. Для корректной коммерческой воронки нельзя использовать смешанный массив всех Goal ID как conversion count.

Следующий аналитический шаг — повторно запросить тот же период/те же десять путей по конкретным ID финальных целей из таблицы выше, не меняя исходную выборку, затем проверить покрытие по более широкому набору страниц и сопоставить события с CRM/реальными заказами. Отдельно нужно проверить, вызываются ли именованные action-события «Обращение. …» при реальной отправке формы или при более раннем клике: их названия сами по себе не доказывают семантику события.

- sessions__counterid;
- sessions__starturl;
- sessions__visitid;

- sessions__goalsorder;
- sessions__goalsprice;
- sessions__offlinecalltag;

Фильтр объединял десять точных путей из таблицы через условие OR по sessions__starturl contains. Для таблицы визитов использован date filter sessions__date. Все 118 строк имеют один и тот же counter ID **1413317** и уникальный visit ID.

Поля были запрошены вместе, а не отдельными разноформатными отчётами. Поэтому числа в таблице и проверка order/call-полей относятся к одному набору из 118 записей.

## 4. Как соотносить с Search Console

Отдельный срез Search Console за тот же 27-дневный период по десяти профессиональным страницам вернул **1 256 показов и 48 кликов**. Эти значения нельзя складывать или напрямую сводить с 118 визитами Метрики: Search Console считает показы и клики в поиске, а Метрика — записанные визиты на сайте. Они отвечают на разные вопросы и не обязаны совпадать.

Результат подтверждает наличие измеряемых входов на часть профессиональных маршрутов, но пока не позволяет посчитать конверсию из клика в обращение или квалифицированную заявку.

## 5. Следующий обязательный шаг

Словарь целей получен и сопоставлен со всеми 21 ID из исходной выборки. Следующий этап — повторить запрос за тем же периодом и по тем же десяти путям, но отдельно выбрать ID финальных целей отправки формы/заявки, сообщения, запроса обратного звонка и заказа из раздела 2.4. Это позволит проверить, какие из этих событий фактически встречаются в выбранном наборе маршрутов, не смешивая их с микроконверсиями.

Затем требуется отдельная проверка покрытия по более широкому набору путей и тестовая проверка реализации событий: в частности, выяснить, при каком конкретном действии срабатывают пользовательские цели «Обращение. …», и соответствует ли это реальной отправке формы. После этого данные по событиям нужно сверить с CRM или другим достоверным реестром квалифицированных обращений и сделок; текущего CRM-коннектора среди подключённых источников нет.

До этих проверок:
- не называть 88 визитов конверсиями или заявками;
- не строить процент «конверсии» по объединённому массиву всех Goal ID;
- не трактовать отсутствие ID финальных целей в данной выборке как доказательство отсутствия обращений вообще;
- не трактовать ноль в order/call-полях как отсутствие коммерческой активности;
- не объединять эти данные с пустой выгрузкой GA4 как будто это нулевой трафик;
- не делать вывод о качестве маршрута только по числу записей.

**Приоритет измерений смещается с наращивания страниц на подтверждение событий отправки и их связь с квалифицированным обращением.**

Выгрузка не содержит доказательств AI-цитирования, квалифицированных лидов, заключённых договоров или выручки. Сайт, настройки Метрики/GA4, цели, теги и публичные материалы не менялись. Платные сервисы и апгрейды не использовались.
