**Режим:** только чтение; настройки счётчика, сайта и событий не менялись.

В них были 5 срабатываний автоцели отправки формы заявки, 16 визитов с отправкой контактных данных, 6 срабатываний action `recall`, 4 — `voice_page`, 3 — `voice-order`. Подробная sitewide-сверка — в разделе 2.5.

## 2. Goal ID не равен заявке

В 88 из 118 записей присутствовал хотя бы один элемент в поле sessions__goalsid. Документация Яндекс Метрики определяет этот массив как ID целей, достигнутых в рамках визита. Первоначальная статистическая выгрузка содержала только числовые ID без имени, типа и условия срабатывания; полный словарь владелец впоследствии получил через read-only Management API и передал для сопоставления (раздел 2.2).

Дополнительные поля были запрошены в том же запросе, с теми же датами, путями и идентификаторами визитов:

- sessions__goalsorder: непустых идентификаторов заказа не найдено;
- sessions__goalsprice: положительных значений цены цели не найдено;
- sessions__offlinecalltag и sessions__offlinecallurl: непустых значений не найдено;
- sessions__offlinecalltalkduration: положительной длительности звонка не найдено;
- sessions__offlinecallmissed: признаков пропущенного звонка не найдено.

Это означает только то, что перечисленные поля не были заполнены в возвращённых записях данного среза. Это **не доказывает отсутствие реальных заказов, звонков или обращений вне этих полей**.

Для расшифровки использован официальный метод списка целей счётчика. Полный словарь теперь позволяет различать поведенческие микроконверсии, общие автоцели формы и контактов, пользовательские action-события и финальные этапы составных воронок. Но само название action-цели не доказывает, что она срабатывает только после успешного коммерческого заказа; для этого требуется проверка реализации и CRM-сверка.

## 2.2. Словарь целей получен: структура и происхождение

21 ноября 2026 года владелец выполнил read-only запрос официального Management API с OAuth-правом `metrika:read` и передал JSON-ответ. Токен вводился локально в PowerShell, не передавался в чат и не включён в этот отчёт или CSV-артефакты. Настройки счётчика и определения целей не менялись.

В ответе API содержатся **88 верхнеуровневых целей**. Семь из них имеют тип `step` и содержат ещё **16 вложенных шагов**. Итого в словаре **104 именованные записи** с уникальными ID, если считать шаги составных целей отдельно. Все 104 записи имеют статус `Active`. Среди 88 верхнеуровневых записей 76 имеют источник `user`, 12 — `auto`. У каждой цели `default_price = 0`; это настройка оценочной цены цели, а не доказательство нулевой выручки.

Распределение типов верхнеуровневых целей: `action` — 62; `step` — 7; `number` — 6; `url` — 3; по одной цели типа `messenger`, `file`, `email`, `form`, `phone`, `social`, `payment_system`, `search`, `contact_data` и `contact_data_sent`.

Официальный метод, которым получен словарь:

`GET https://api-metrika.yandex.net/management/v1/counter/1413317/goals`

Он возвращает ID, имя, тип, статус и условия/параметры цели. В отличие от прежней статистической выгрузки, владелецкий JSON содержит само соответствие ID → определение цели.

### Совпадения и дубли в целях

- ID 245247724 и 339058736 встречаются в одних и тех же **16 визитах**. В них зафиксированы как ввод, так и отправка контактных данных.
- ID 35137209 и 140906170 настроены на один и тот же exact event `voice_page`; в контрольной выборке они совпали во всех четырёх визитах.
- ID 40911079 и 140905951 настроены на один и тот же exact event `voice-order`; в контрольной выборке они совпали во всех трёх визитах.
- Поэтому пары целей «Заказ…» и «Обращение…» нельзя складывать как отдельные действия: в каждой паре две записи целей привязаны к одному event label.
- Три пользовательские action-цели 47559229, 35137209 и 40911079 охватывают **13 различных визитов** без пересечений между этими тремя наборами. Остальные action-события требуют проверки реализации и не должны автоматически трактоваться как подтверждённый заказ/звонок.

У пяти визитов с ID 233561977 стартовые страницы были в каталоге/профилях дикторов; все пять имели source organic. Два визита с ID 40911079 начинались на страницах каталога дикторов, один — с главной страницы. Это значения `sessions__starturl`, то есть стартовые страницы визита, а не отдельное доказательство конкретного URL, где был выполнен submit.

- Для цели ввода контактных данных 245247724 получено 101 view-level запись, для цели отправки контактных данных 339058736 — 44. В этих page-view записях встречаются, помимо сервисных страниц, страницы вакансий, входа/аккаунта и интерфейсы `audio.plus`; это дополнительная причина не приравнивать каждую запись contact-data к продаже или квалифицированному лиду.
- Синтетический `goal://`, `form://` или `autogoal://` URL — внутреннее представление события, а не публичная посадочная страница.

Yandex описывает автоцели отправки формы и передачи контактных данных отдельно; в частности, автоцель формы охватывает отправку форм, а `contact_data_sent` означает отправку контактных данных и может достигаться при передаче только одного контактного поля. Поэтому generic form/contact-data events требуют проверки контекста, а не механического подсчёта как заявок. См. официальную документацию в разделе 6.

## 2.6. Практический вывод для аналитики

Показатель «88 визитов с Goal ID» на десяти выбранных профессиональных маршрутах действительно состоял из 21 поведенческого/навигационного ID и не включал финальные цели отправки. Однако отдельный фильтр по всему счётчику за тот же период выявил пять автоцелей отправки формы заявки, 16 визитов с отправкой контактных данных и пользовательские action-события обратного звонка/заказа на страницах дикторов. Следовательно, первоначальный вывод был верен только для ограниченной выборки десяти маршрутов, но не для сайта в целом.

При этом 72 визита широкого запроса нельзя назвать 72 лидами: каждый попал в выборку через один или более отобранных Goal ID, а общая автоцель отправки формы встретилась во всех 72. Contact-data events включают контексты вакансий, аккаунта и продукта audio.plus; action-цели с одинаковыми event labels дублируются парами. CRM-источника для проверки квалификации и результата нет.

## 4. Как соотносить с Search Console

Отдельный срез Search Console за тот же 27-дневный период по десяти профессиональным страницам вернул **1 256 показов и 48 кликов**. Эти значения нельзя складывать или напрямую сводить с 118 визитами Метрики: Search Console считает показы и клики в поиске, а Метрика — записанные визиты на сайте. Они отвечают на разные вопросы и не обязаны совпадать.

Результат подтверждает наличие измеряемых входов на часть профессиональных маршрутов, но пока не позволяет посчитать конверсию из клика в обращение или квалифицированную заявку.
