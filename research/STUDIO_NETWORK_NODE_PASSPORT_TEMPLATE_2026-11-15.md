# Паспорт узла распределённой сети студий «Аудио-Реклама•ru»

## 0. Назначение и границы

Этот шаблон нужен, чтобы описывать реальные локальные студии, в которых записываются дикторы из базы «Аудио-Реклама•ru».

Владелец подтвердил 15.11.2026, что почти каждый диктор в базе записывает на студии по месту своего расположения и что совокупность этих точек образует распределённую сеть. Основание: [E-2026-046](../evidence/E-2026-046.md).

**Это шаблон сбора данных, а не норматив приёмки.** Пока не собраны и не измерены реальные узлы, нельзя назначать универсальные лимиты шума, RT60, формата записи или обязательные модели техники.

Один паспорт описывает одну физическую студийную точку / один устойчивый recording setup. Если одна площадка имеет несколько существенно разных комнат или трактов, на каждый setup создаётся отдельный паспорт с общей ссылкой на площадку.

Не путать:
- диктора — человека, который исполняет запись;
- узел сети — локальную студийную точку, в которой производится запись;
- производственную координацию — кастинг, постановку задачи, режиссуру, передачу исходников и организацию дублей;
- постпроизводство — монтаж, обработку, сведение и подготовку файлов;
- клиентскую выдачу — конечный файл и спецификацию заказчика.

Не предполагать, что все площадки принадлежат одной компании, работают эксклюзивно, имеют одинаковую технику или проходят одинаковую акустическую сертификацию.

## 1. Идентификация узла

| Поле | Заполнить |
|---|---|
| node_id | Устойчивый внутренний ID, не имя человека |
| Название площадки | Как можно идентифицировать студию внутри сети |
| Город / регион / страна | Достаточно географии до уровня города или региона; не публиковать точный адрес |
| Связанные профили дикторов | URL или внутренние ID карточек каталога |
| Тип отношений | UNKNOWN / партнёр / независимая площадка / договорная площадка / собственная площадка / другое — только после подтверждения |
| Ответственный за технику | Роль или рабочий контакт в защищённой внутренней системе |
| Статус | proposed / active / temporarily-unavailable / suspended / retired |
| Последняя проверка | Дата и кто подтвердил сведения |
| Следующая проверка | Дата или условие повторной проверки |

**Статус отношений не выводить из географии, названия профиля или марки оборудования.**

## 2. Помещение и акустика

| Поле | Заполнить |
|---|---|
| Тип помещения | Отдельная дикторская / контрольная / совмещённая / мобильная / другое |
| Габариты | Длина × ширина × высота, если измерены |
| Акустическая обработка | Что установлено и где; не путать панели с полноценной звукоизоляцией |
| Внешние шумы | Вентиляция, улица, компьютеры, соседи, транспорт и т. п. |
| Noise floor | Измерение, единицы, метод, прибор, точка измерения и условия |
| RT60 | Значения по полосам, метод, положение микрофона и условия измерения |
| Мониторинг | Наушники / мониторы, модель и способ контроля |
| Дата акустической проверки | Дата и ответственный |

Если измерений нет, писать UNKNOWN. Фотография помещения не заменяет измерение, а субъективное «тихо» не превращать в число.

## 3. Реальная сигнал-цепь записи

Заполнять фактический маршрут сигнала, а не просто список принадлежащих площадке устройств.

`Микрофон → предусилитель (если отдельный) → аудиоинтерфейс / конвертер → локальный компьютер → DAW → исходный локальный файл`

| Звено | Модель / версия | Как используется | Основное / резерв | Подтверждение |
|---|---|---|---|---|
| Микрофон | | | | |
| Поп-фильтр / крепление | | | | |
| Предусилитель | | | | |
| Аудиоинтерфейс / конвертер | | | | |
| Компьютер / ОС | | | | |
| DAW / версия | | | | |
| Мониторинг / наушники | | | | |
| Аппаратная обработка | | | | |
| Плагины / версии | | | | |

Для каждого звена отмечать:
- фактически используемое устройство, а не то, что просто есть в комнате;
- где возникает аналоговое усиление и где выполняется A/D-преобразование;
- какие функции включены при записи (AGC, gate, denoise, EQ, compression и т. п.);
- сохраняется ли чистый исходник до обработки;
- что произойдёт при отказе основного звена.

Не выводить качество узла только из дорогой марки микрофона. Полная цепь, помещение, оператор, положение микрофона и исходная запись важнее отдельного бренда.

## 7. Контроль качества узла и тестовый пакет

На первом этапе это сбор результатов, а не pass/fail-рейтинг.

Минимальный воспроизводимый тест:
1. Короткий согласованный тестовый текст с обычной и громкой речью.
2. Отдельная запись тишины / room tone.
3. Необработанный файл до шумоподавления, компрессии и эквализации.
4. Краткая проверка plosives, клиппинга, фонового шума, реверберации, треска, пропусков и разборчивости.
5. Повторяемый фрагмент на том же тракте после перезапуска сессии.
6. Фиксация файла, настроек, даты, исполнителя и проверяющего.

Использовать [VOICE_RECORDING_TEST_PROTOCOL](../problem-solutions/VOICE_RECORDING_TEST_PROTOCOL.md) для положения микрофона, gain, фонового шума и сравнений обработки. Не объявлять тест завершённым, пока не сохранены исходники, условия, метод и результат.

Численные пороги для сети утверждать только после сбора реальных baseline-данных и определения требований отдельных каналов доставки. Нельзя автоматически применять к каждому узлу один и тот же RT60, noise floor или экспортный формат.

## 9. Статус каждого поля и происхождение

Каждое существенное значение сопровождается:
- статусом: `owner-confirmed`, `talent-confirmed`, `measured`, `profile-listed`, `unknown`, `stale`, `not-applicable`;
- датой проверки;
- источником: профиль диктора, ответ ответственного, фотография маркировки, отчёт DAW, измерение или тестовый файл;
- ответственным за подтверждение.

Не смешивать:
- **profile-listed** — написано в публичной карточке;
- **owner-confirmed / talent-confirmed** — человек подтвердил фактическое использование;
- **measured** — результат получен воспроизводимым измерением;
- **unknown** — данных нет или они не проверены.

## 10. Решение по узлу — только после сбора фактов

До появления согласованной политики не присваивать узлу оценки «прошёл / не прошёл» на основании одного микрофона, наушников, названия DAW или отсутствия дорогой аппаратуры.

После пилота можно отдельно определить:
- минимальные требования к исходной записи;
- проверяемые критерии комнаты;
- обязательные локальные и центральные QC-шаги;
- требования к передаче и хранению;
- процесс обновления / временного отключения узла;
- процедуру повторной квалификации после изменения оборудования или помещения.

Это станет отдельным утверждаемым стандартом только после фактического обследования сети и проверки нескольких репрезентативных узлов.
