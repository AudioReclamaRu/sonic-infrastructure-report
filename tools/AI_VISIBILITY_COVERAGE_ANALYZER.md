# AI Visibility Coverage Analyzer

The analyzer compares planned queue cells with manually collected benchmark observations. It is offline and read-only: it does not contact providers, run measurements, modify a website, or spend credits.

## Run

Plan-only coverage (all planned cells will be reported as missing observations):

```bash
python tools/ai_visibility_coverage.py \
  --queue research/queues/ru-generic-discovery-queue.csv \
  --queue research/queues/ru-brand-service-queue.csv \
  --json-out reports/ai-visibility/coverage.json \
  --markdown-out reports/ai-visibility/coverage.md
```

Coverage against a collected benchmark CSV:

```bash
python tools/ai_visibility_coverage.py \
  --queue research/queues/ru-generic-discovery-queue.csv \
  --queue research/queues/ru-brand-service-queue.csv \
  --observations research/ai-visibility-observations.csv \
  --json-out reports/ai-visibility/coverage.json \
  --markdown-out reports/ai-visibility/coverage.md
```

Repeat `--queue` for each module. The tool expects the queue schema generated by `ai_visibility_queue.py` and the observation columns used by `ai_visibility_benchmark.py`.

## Report semantics

- Planned cells are the query × platform × measurement-mode × market/locale identities in queue files.
- Observed cells are planned identities with at least one matching observation row.
- Repeated collection attempts do not inflate cell coverage; they remain visible in observation row and answer-status totals.
- `OK` and `PARTIAL` are answered observations. Blocked, unavailable, unsupported, error and not-tested statuses count as collection coverage when they match a planned cell, but are never interpreted as zero visibility.
- The report does not calculate visibility rates. Use the benchmark summarizer for answered-only scoring.
- Consumer UI, model API and search-results UI remain separate dimensions.
- Market and region verification are read from explicit queue/observation fields; the analyzer never infers a Russian vantage point from the machine running it.
- Missing and unexpected observations, duplicate planned cells, duplicate observation IDs, invalid statuses and mutated planned queue statuses are reported as errors.
