# CULTURE OF VOICE — EDITORIAL OBJECT CASES

**Исследование одной строкой (владелец, 30.09.2026):** можно ли получить объект,
который ощущается неизбежным, не зная заранее, каким он должен быть?

Эталонные живые кейсы: событие → настоящий объект → почему такая обложка
правильная → почему три другие неправильные. Заполняется человеком вручную
(правило §9 editorial-object-contract.md, DoD-заморозка §10). CASE 01 заполнен
по slotu kast-kharakterov-2026-09-27 (единственная published-публикация в режиме B).

**Контрольный вопрос каждого кейса:** если убрать заголовок и весь текст, можно
ли по одной обложке понять, какое именно изменение произошло?

**OBJECT VALIDATION (неслучайность, §6 контракта):** если объект можно заменить
другим без потери смысла — объект слабый (выбран неверно). Объект обязан быть
следом МЕХАНИЗМА (событие → переход → открытое состояние → объект), а не
символом, придуманным редактором (редактор придумал «дверь» → провал модели).

CASE 02–05 НЕ заполнять автоматически. Человек руками задаёт:
`BEFORE / CHANGE / AFTER / MECHANISM / EVIDENCE / OBJECT_TYPE`, система проверяет,
способна ли она построить целостную новость без ручной подсказки обложке.

**REPLACEMENT NOTES (обязательный артефакт испытаний, заполняется при каждом
CASE 02–05).** Это человеческий аналог будущего OBJECT PRESSURE: фиксируется по
горячему, без «причёсывания»:

```
Первый объект: ...
Объект, который захотелось поставить вместо него: ...
Почему захотелось заменить: ...
Почему не удалось заменить: ...
```

Если после просмотра CASE возникает «можно заменить чем угодно» — объект не
закрепился за механизмом. Если «нет, именно этот объект здесь неизбежен» —
найден след, а не символ. Эти заметки дадут материал для будущего OBJECT
PRESSURE, если он вообще понадобится.

## CASE 01 — SPLIT (ЗАКРЫТО)

```
EVENT:
  Слепой тест Edison Multi-Cast: каст ролей обгоняет один универсальный голос
  и ведёт слушателя по драматургии выбора бренда.

OBJECT_TYPE: SPLIT
  Один голосовой субъект расщепляется на несколько персонажей-ролей.

EVENT OBJECT:
  subject:    голос
  action:     порождает несколько ролей
  before:     один универсальный голос в слепом тесте
  after:      несколько отдельных голосов-персонажей, каждый со своим характером
  mechanism:  Edison Multi-Cast: один маршрут голоса расщепляется на варианты
              персонажей внутри одной записи
  consequence: персонаж и ведущий конкурируют как субъекты; у канала появляется
              несколько голосов из одной записи
  evidence:   слепой тест Edison Multi-Cast, каст ролей впереди

BACKGROUND_OBJECT (след механизма):
  микрофон — структурный источник сигнала, от которого расходятся тени-роли.
  Не заменим вазой/лампой: это именно то, из чего расщепляется голос.


RIGHT:
  [концепция: микрофон, чей голос расщепляется на четыре фигуры-роли —
  одна говорит, три слушают]
  Микрофон — источник сигнала; от него расходятся четыре тени-роли; единственный
  красный акцент в точке расщепления. Обложка отвечает «что произошло с
  реальностью»: один источник стал несколькими субъектами. Без текста читается
  переход, а не тема.

WRONG:
  [тематическая картинка] Микрофон + человек + наушники на красном фоне.
  Говорит только «это про голос», не несёт изменения.

  [буквальная иллюстрация] Логотип/скриншот продукта Edison Multi-Cast или
  четыре отдельных исполнителя в студии. Иллюстрирует состав события, а не
  переход «один стало несколькими».

  [абстрактная красота] Размытый красно-чёрный градиент без предмета, где
  «красиво», но не видно, что именно изменилось.

OBJECT VALIDATION:
  Можно ли заменить микрофон другим объектом без потери смысла? Нет: механизм
  = расщепление голосового источника, поэтому объект обязан быть источником
  сигнала. Замена на вазу/лампу/крестик теряет механизм.

REASON:
  Обложка должна показывать ИЗМЕНЕНИЕ (transition), а не тему и не состав.
  Для SPLIT изменение = один источник → несколько субъектов. Правильное решение
  кодирует это одним объектом (источник + расходящиеся контуры) и одной точкой
  красного в месте разрыва. Всё, что рисует «голос» без разрыва единого
  источника, — иллюстрация темы; что рисует готовый результат без генетической
  связи с источником — буквальная иллюстрация; что не рисует предмета — пустой
  декор.
```

## CASE 02 — TRANSFORMATION (ЗАПОЛНЕН 30.09.2026, живой факт)

Доказывает: **то же самое → уже другое**. Контрольный вопрос: по одной обложке
видно, что предмет трансформировался, а не просто «есть предмет»?

Исследовательский вопрос: изменился ли человек настолько, что объект прошлого
состояния перестал ему соответствовать?

ФАКТ (владелец, 30.09.2026):
человек 12 лет работал в одной компании. Последний рабочий день прошёл спокойно,
без конфликта. Сдал пропуск, вышел из здания. Через несколько минут вернулся —
не за документами, не за вещами, не попрощаться. Подошёл к своему бывшему столу,
снял приклеенную сбоку маленькую бумажку с номером внутреннего телефона, сложил
её в карман и ушёл окончательно. Больше в компанию не возвращался.

```
BEFORE: бумажка с номером внутреннего телефона была живым инструментом связи
        внутри компании
CHANGE: человек вышел из внутреннего контура (сдал пропуск); номер перестал
        соединять
AFTER:  номер мёртв — набор ничего не соединяет; бумажка лежит в его кармане
MECHANISM: внутренний номер соединяет, только пока человек в составе контура;
        разрыв связи делает номер мёртвым, но предмет остаётся и уносится прочь
EVIDENCE: человек спустя минуты после выхода вернулся, НЕ за вещами, снял
        бумажку со стола и ушёл навсегда
EVENT: человек уносит из компании единственный отобранный предмет — бумажку
        с номером, который уже не соединяет
OBJECT_TYPE: TRANSFORMATION

BACKGROUND_OBJECT (след механизма):
        маленькая бумажка с номером внутреннего телефона, отклеенная от стола
        и унесённая в карман. Это дословно предмет из mechanism («предмет
        остаётся и уносится прочь») — единственное, что человек сам выбрал
        и вынес.

RIGHT:
        бумажка с номером, снятая со стола, складывается и уходит в тёмный
        карман; маленький красный акцент на цифрах номера — точка, где связь
        оборвана. Читается переход: рабочий инструмент связи перестал работать
        и стал личной вещью на вынос.

WRONG:
  [пустой стол с отпечатком клея] — показывает пустоту, но не несёт унесённый
        предмет с номером; читается как «что-то убрали», а не «связь унесли
        прочь» (ABSENCE, не TRANSFORMATION).

  [сданный пропуск на стойке] — пропуск человек СДАЛ, а не унёс; работает как
        «официально вышел», но номер-связь отсутствует.

  [кружка / ваза / лампа на столе] — чужие предметы обстановки; тема «кабинет»,
        а не «внутренняя связь умерла и унесена».

OBJECT VALIDATION:
        Проверка заменяемости: отпечаток на столе не несёт унесённого предмета
        с номером; пропуск — сдан, а не вынесен; кружка/ваза не связаны с
        внутренним номером. Только бумажка совпадает с mechanism сразу в двух
        половинах: «предмет остаётся» (пережил обрыв) и «уносится прочь»
        (единственное, что унёс).

REASON:
        Обложка обязана показать ИЗМЕНЕНИЕ: одно и то же (номер) перестало
        соединять и переместилось из контура в карман. Бумажка — самый сильный
        носитель: она связывает mechanism, evidence (он вернулся именно за ней)
        и после-состояние (в кармане). Всё прочее рисует либо факт увольнения
        (пропуск), либо его последствие-пустоту (стол), либо посторонний
        предмет.

REPLACEMENT NOTES:
  Первый объект: маленькая бумажка с номером внутреннего телефона, унесённая в карман
  Объект, который захотелось поставить вместо него:
        сначала — сданный пропуск (самый «редакционно очевидный» символ
        увольнения); затем — отпечаток/пустой стол.
  Почему захотелось заменить: пропуск мгновенно «читается» любой аудиторией
        как «человек ушёл с работы»; бумажка-в-кармане требует догадки «что
        это», поэтому первая реакция — подменять её на «понятный» символ.
  Почему не удалось заменить:
        пропуск — это ВХОД/ДОСТУП, его человек сдал (в компанию не возвращается
        именно потому, что доступ закрыт); но на кейсе висит не «потеря
        доступа», а «унесённая внутренняя связь» — пропуск разрывает mechanism
        (связь, а не доступ). Отпечаток/пустой стол — ABSENCE, показывают
        отсутствие, а не унесённый предмет с номером. Замена не удалась:
        пропуск и стол теряют механизм «предмет, который соединял, остаётся
        и уносится прочь». /* исключительно из-за этого объект-бумажка остался
        первым */
```

**Прокси-наблюдения (записаны, код НЕ тронут — observe mode):**

- `object_validation` на бумажке прошла (`[]`); на пропуске, кружке, вазе, пустом
  столе — тоже `[]` в варианте mechanism со словом «столе» (лексическое
  загрязнение поля). В чистой формулировке mechanism (без «на столе») кружка
  всё равно прошла — пересечение по морфокорню «оста-» («осталась»/«остаётся»).
  Это предел прокси O-корня: он ловит «мёртвую» лексику, а не различение силы.
- `cover_semantic` на бумажке — `SEMANTIC_MISMATCH` (в визуальном объекте нет
  маркеров изменения из CASE-словаря SPLIT/ветвление). Ожидаемо: словарь маркеров
  пока тянет только часть типов перехода. Не меняем до закрытия CASE 02–05.
- VALID BUT WEAK фиксируется как наблюдаемое явление: «пропуск» — прошёл trace
  (первый кандидат на замену), но разрушает mechanism. Это ровно тот случай,
  который предсказал владелец.
