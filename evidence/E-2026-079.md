# E-2026-079 — AI visibility measurement boundary for the Russian market

## Purpose

Record why the connected OpenSEO tracker must not be used as a Russia-market baseline at present, and preserve the no-spend / no-false-geography decision.

## 1. Observed connected-project state (19 November 2026)

OpenSEO project:
- Project name: «Аудио-Реклама•ru — AI Discovery»
- Project ID: f868933a-0943-4722-b8f1-d54ceb5d34a9
- Domain: audio-reclama.ru
- Default language: English (en)
- Default location code: 2840 (United States)
- Provider connection: configured
- AI visibility tracker: not configured
- Tracker: absent
- Prompts, topics, engines and recent runs: none
- No AI-visibility check was started and no recurring schedule was enabled.

Interpretation:
- The project’s default market is not Russia. Any US/English report would describe a different market and language, not the company's Russia-first discovery baseline.
- Saving a new tracker in this tool starts a weekly schedule by default; scheduled checks consume paid credits. Do not save or enable it until a suitable market path and explicit spend authorization exist.
- Do not interpret an empty tracker or absence of reports as zero visibility.

## 2. Provider's Russia/Belarus location exclusion

Official DataForSEO documentation:
- ChatGPT LLM Scraper locations: https://docs.dataforseo.com/v3/ai_optimization-llm_scraper-locations/
- Google SERP locations: https://docs.dataforseo.com/v3/serp/google/locations/
- General DataForSEO terms: https://dataforseo.com/terms-of-service

The ChatGPT LLM Scraper locations page and multiple DataForSEO location documentation pages state that **all locations in Russia and Belarus are no longer supported across DataForSEO services**. The current location export is dated 2 November 2026. The general terms also contain a separate service-eligibility restriction for users located, incorporated, established or resident in specified jurisdictions; this record does not infer the connected account holder's status and does not make a legal determination.

Measurement consequence:
- A DataForSEO-backed AI answer check cannot be represented as a Russian-location observation for this project.
- Do not substitute USA, Netherlands or another country and label it RU.
- Do not use a proxy/VPN to imply a false consumer location.
- Do not infer Russian-market absence from a failed/unsupported request.

## 3. Valid route for the Russia-first baseline

The repository already contains fixed, unbranded Russian generic discovery prompts and a separate brand/service set:
- `research/ai-visibility-ru-generic-discovery-queries-2026-11-17.json`
- `research/ai-visibility-benchmark-queries-2026-11-17.json`
- `research/ai-visibility-ru-observation-queue-2026-11-17.csv`

Use the measurement protocol already defined there:
- Run the exact prompts in fresh consumer-facing sessions available in the actual target market.
- Record exact product, interface/surface, date/time, language, region evidence, account state, search/grounding mode, complete answer and cited URLs.
- Keep consumer UI, search-results UI and model API observations separate.
- Mark unavailable, blocked, unsupported, failed and no-answer distinctly; do not call them zero visibility.
- Do not prime generic prompts with the brand name.
- Preserve full answers and source URLs.

This is a manual evidence-capture route, not an automated OpenSEO tracker. Its coverage must be reported by platform and query, without extrapolating to all AI products.
