# E-2026-089

## Short statement

15.11.2026 при прямой live-проверке официального сайта Audio-Reclama.ru подтверждено:

1. XML sitemap открывается с HTTP 200 и содержит 1 186 уникальных URL. Все 1 186 записей имеют changefreq=daily; элементов lastmod в файле нет.
2. Два URL профилей дикторов возвращают HTTP 404, но оба включены в sitemap:
   - Наталья Беленькая: https://www.audio-reclama.ru/diktoryi/zhenskie-diktor-golosa/russian-diktor-natalia-belenkaia.html
   - Yavor: https://www.audio-reclama.ru/diktoryi/inostrannye-diktor-golosa/bulgarian-diktor-yavor.html
3. Старый URL /clients.html включён в sitemap, но live-запрос завершается на /feedbacks.html (HTTP 200). Точный исходный HTTP-код перенаправления в этом инструментальном снимке не зафиксирован.
4. robots.txt содержит Disallow: /en/* и Allow: /en/. Sitemap включает корень /en/, но не включает три проверенных английских страницы проектов; эти страницы открываются напрямую с HTTP 200 и связаны внутренними ссылками с английской главной страницей.
5. В четырёх проверенных шаблонах — главная, каталог дикторов, страница IVR и английская главная — в возвращённом raw HTML не обнаружен тег rel="canonical". Это утверждение относится только к выборке из четырёх страниц, не ко всему сайту.
6. Метаописание страницы IVR содержит «Цена от 1000 р. Срок готовности – 1 день», но ни цена 1000 рублей, ни срок в один день не найдены в видимом тексте страницы. Их фактическая применимость не установлена; требуется подтверждение владельца услуги.
7. Метаописание главной страницы говорит об «искусстве звука» и «утончённости идей», но не называет основные коммерческие направления, которые видны в навигации и содержании сайта.

**p = 1,0** относится ровно к содержимому и HTTP-статусам указанных live-ответов официального сайта на 15.11.2026, а также к тексту действующей документации Google, указанной ниже. Это не доказывает, что поисковик уже исключил 404, не индексирует английские страницы или выбрал конкретный canonical. Фактические показы, клики, позиции, сессии и обращения не измерены.

## External primary technical source

Google Search Central — How Google Interprets the robots.txt Specification:
https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec

The specification states that Google uses the most specific matching rule based on rule-path length; in a conflict between rules of equal specificity it uses the least restrictive rule. For a nested English URL such as /en/project/globus-group.html, Disallow: /en/* is a longer matching path than Allow: /en/. Under Google's published matching algorithm, the more specific Disallow applies. This is a rules-based interpretation of the currently published robots file, not evidence from Search Console that a particular URL is or is not indexed.

Google Search Central — Build and Submit a Sitemap:
https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap

Google advises including canonical URLs intended for search results; sitemap submission is a hint, not an indexing guarantee.

Google Search Central — How to Specify a Canonical with rel="canonical" and Other Methods:
https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls

Google recommends consistent canonical signals and a self-referential canonical on canonical pages, but absence of a tag in a sample does not by itself prove an indexing defect; Google can select a canonical independently.

- It does not establish that the homepage meta description causes a lower click-through rate; it records a concrete opportunity to make the snippet more descriptive.
- It does not prove that the absence of rel="canonical" on four sample pages is a site-wide problem.
- It does not validate every URL in the 1,186-entry sitemap. Only the two 404 entries, one redirecting entry and three English project URLs received individual checks in this snapshot.
