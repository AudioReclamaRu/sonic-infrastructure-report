# E-2026-082 — X: independent read and repost automation without Metricool

## Purpose

Identify official and lower-dependency ways to read public X content and operate the existing owner-supplied company account `@audioreclamaru`, without adding the Metricool X add-on.

## 1. Separate xAI API from X API

These are two distinct products:

- **xAI API** (`https://api.x.ai/v1`) serves Grok models. Its built-in `x_search` tool can search X by keywords/meaning, look up users, fetch threads, constrain results to up to 20 specific handles with `allowed_x_handles`, restrict dates, and inspect post images/videos.
- **X API** (`https://api.x.com`) is the social platform API. It exposes read endpoints, post creation and repost actions under user authorization.

The xAI API is suitable as a research/discovery layer. It is not the API that writes posts or performs reposts on the X account. The xAI API documentation describes search, not posting as a social account.

Official sources:
- xAI X Search: https://docs.x.ai/developers/tools/x-search
- xAI pricing: https://docs.x.ai/developers/pricing
- X API getting access: https://docs.x.com/x-api/getting-started/getting-access
- X API pricing: https://docs.x.com/x-api/getting-started/pricing

## 2. Official X API: one integration can read and repost

X Developer Platform currently documents pay-per-use credits, with no subscription or minimum spend. Credits are purchased in advance; spending limits can be configured in the Developer Console.

Current published unit costs observed 19 November 2026:
- Public Posts: Read — **$0.005 per returned post**.
- User: Read — **$0.010 per returned profile**.
- Own posts and certain other own-account resources — **$0.001 per resource** when the request is made by the developer app owner and the queried user ID is the authenticated user.
- Post: Create — **$0.015 per request** (a post containing a URL is listed separately at $0.200).
- User Interaction: Create — **$0.015 per request**; this is the action bucket relevant to user interactions such as reposts, subject to the endpoint's current console classification.
- Same resources are generally deduplicated within a 24-hour UTC window.

These are published reference prices, not a quote or authorization to buy credits. Rates can change; the Developer Console is authoritative. Do not enable auto-recharge.

Official source: https://docs.x.com/x-api/getting-started/pricing

Relevant capabilities:
- Read public posts using app-only Bearer Token (read-only).
- Read own account posts through `GET /2/users/{id}/tweets`; qualified own reads are listed at $0.001/resource.
- Repost a post with `POST /2/users/:id/retweets`, where `:id` is the authenticated account's user ID and the body includes `tweet_id`.
- Create original posts with `POST /2/tweets`.

Official references:
- https://docs.x.com/x-api/getting-started/getting-access
- https://github.com/xdevplatform/samples/blob/main/api-index.json
- https://github.com/xdevplatform/docs/blob/main/x-api/posts/retweets/integrate.mdx
- https://docs.x.com/fundamentals/developer-apps

### Authentication detail

Reading public content can use an app Bearer Token. Posting/reposting requires user-context authorization for the company account. X's current documentation describes OAuth 1.0a Read and Write permissions; the dedicated Retweets integration guide says managed repost endpoints require OAuth 1.0a User Context. Some SDK/sample material also lists OAuth 2.0 User Context, so the implementation must follow the current endpoint reference and verify the enabled authentication mode before use. Never use a password in a script or paste any token into ChatGPT.

## 3. xAI X Search as a separate discovery layer

Official xAI pricing:
- X Search: **$5 per 1,000 posts fetched** and **$10 per 1,000 user profiles fetched**, plus Grok text-token charges.
- The API reports exact fetched-post and fetched-profile usage counters.
- Handles and date ranges can narrow the search, reducing unnecessary retrieval.

Official sources:
- https://docs.x.ai/developers/tools/x-search
- https://docs.x.ai/developers/pricing

This can power a separate research pass to identify:
- relevant sector news (voiceover, audio-production, advertising, localization, IVR, branded audio);
- posts from selected clients, partners, festivals and professional sources;
- mentions of the company or its projects;
- candidate posts suitable for a native repost rather than copying content.

No xAI API key or credits are currently connected or approved for spend.

## 4. Public read-only fallback: FxEmbed / FxTwitter

FxEmbed publishes a public, unauthenticated X/Twitter data API with profile, media timeline, search, trend and thread endpoints. For example, the documented profile endpoint is:
`GET https://api.fxtwitter.com/2/profile/{handle}`.

This is an independent third-party service, not an official X API, and it is read-only for this workflow. It may be useful as a no-credential fallback for public-profile research, but data availability, stability and platform compatibility are not guaranteed. It does not authorize or perform account reposts.

Official FxEmbed API docs:
- https://docs.fxembed.com/api/introduction/
- https://docs.fxembed.com/api/twitter/operations/2profilehandle/
- https://docs.fxembed.com/api/twitter/operations/2profilehandlemedia/

## 5. Connector audit

- Metricool: the existing brand (ID `8189992`) currently lists Facebook, Instagram, TikTok and YouTube, but not X. Its X add-on is a separate paid product and is not required for the direct API route.
- Windsor.ai `twitter` and `x_organic` connectors are available in the connector catalog, but their exposed write-action lists are empty. They cannot perform reposts through the current connected-app tools.
- No OAuth account, API key, app, credits, or post/repost action was configured in this review.

## 6. Proposed operating design

Use one small, auditable X integration with two distinct stages:

### Read / discovery
- Prefer official X API for exact own-account timeline and mentions, plus optional public-post searches.
- Optionally use xAI X Search for semantic discovery and source analysis, only after the owner approves a small prepaid budget.
- A third-party public viewer/API may be used for a limited read-only spot-check, never as the only source of record.

### Repost / publish
- Use the official X API and account-authorized user context.
- Start with a **candidate queue**, not blanket automatic reposting.
- Repost only public, relevant, non-duplicative posts from credible accounts that materially relate to audio-production, voice talent, localization, advertising, IVR, branded audio, or verified company/project activity.
- Exclude politics, controversial topics, unrelated viral content, competitors' direct sales, unverified claims, sensitive customer material, copyright-heavy media, and posts that could imply a client relationship or endorsement not established.
- Keep an idempotency log of source post IDs; do not repost the same post twice.
- Use conservative rate limits and platform-compliant API access. No browser macros, scraping private posts, mass-following, automated likes, unsolicited DMs or engagement loops.
- For the first phase, use automatic read/triage and prepare a small candidate queue; actual reposting should be executed only after source, context and account authorization have been checked. After quality and operational reliability are established, an explicitly bounded allowlist/criteria-based auto-repost mode can be considered.

## 7. X automation-policy requirements

X's automation rules, updated April 2026, explicitly permit automated reposts/quote posts for informational, entertainment or novelty purposes when the wider rules are followed. They prohibit bulk, aggressive or spammy reposting and prohibit non-API website scripting. For automated actions through an owner's account, X requires the app to describe the actions clearly, obtain express consent, and honor opt-out requests immediately.

The company owner has expressly requested relevant autonomous reposting in this conversation. The implementation must still:
- describe the permitted action scope clearly in its own settings/readme;
- provide a simple global pause/opt-out switch;
- enforce a low repost cadence and source/topic filters;
- log every repost and avoid duplicates;
- never automate likes, follows, replies, mentions or DMs;
- stop instantly when the owner disables the workflow.

Official source: https://help.x.com/en/rules-and-policies/x-automation

## 8. Next setup gate

The only unavoidable owner-side step for direct official publishing is to create/enable an X Developer App and authorize the existing company account:

1. Open https://console.x.com/ while signed in as the owner of `@audioreclamaru`.
2. Accept the Developer Agreement and create a new app (or use an existing app if one already exists).
3. Configure the app for the minimum Read and Write permissions needed for posts/reposts; do not enable DMs.
4. Store generated app credentials and the account-authorized access tokens in a password manager or the eventual runtime's secret store; do not send credentials through chat.
5. Do not buy credits or enable auto-recharge without explicit approval. The current official X API uses prepaid credits even though it has no fixed monthly subscription.

After that connection exists, the automation can read the company's own posts, research candidates, and submit authorized reposts through the official endpoint, with every action logged.
